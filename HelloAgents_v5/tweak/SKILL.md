# 微调模式（T）

## 目标

- 对明确的小改动快速落地，减少流程成本。

## 适用范围

- 目标明确，改动路径清晰。
- 推荐上限：≤2个文件、≤30行核心改动。
- 不涉及 EHRB 风险。

## 执行步骤

1. 精准定位目标文件和代码段。
2. 开始改动前强确认（安全门禁）
   - 若 `WORKFLOW_MODE=AUTO_FULL`：视为用户已授权连续执行，可跳过口令门禁；但必须在输出中显式标注“当前为 AUTO_FULL，将直接写入”。（见 `references/state.md`）
   - 交互模式强确认口令（任一匹配即视为确认）：`确认开始实现` / `确认开始代码实现` / `确认开始落地`
   - 未确认时：必须使用 `templates/output-format.md` 的 **G6.4 交互询问输出格式** 输出“强确认：是否开始实现”，并停止；只允许继续只读分析，不允许任何写入。
3. 小步修改并即时自检。
4. 运行最小相关验证。
5. 同步知识库（必要时先 `~init` 初始化知识库骨架）。
6. （当 `DELIVERY_MODE=CLOSE_LOOP`）生成/更新 `helloagents/wiki/memories` 记忆体与索引，并执行本地 git commit（不 push）。
7. 记录变更并结束流程。

## 升级条件

满足任一条件即升级到标准流程（`analyze → design → develop`）：
- 实际改动超过范围上限。
- 发现跨模块依赖。
- 触发 EHRB 风险信号。
- 用户要求补充方案文档。
- 若已有方案包（`helloagents/plan/**`）且复杂度升级：需要同步更新 `why.md` 元信息 `@complexity_review`（脚本：`scripts/update_package_metadata.py`；无脚本：手工更新）。

## 输出要求

- 使用 `templates/output-format.md`。
- 输出必须包含：变更摘要、验证结果、是否触发升级；若执行闭环交付，补充：记忆体路径与 commit 哈希（如可获取）。

## 阶段退出条件

- 微调完成并验证通过。
- 或升级到标准流程继续执行。
