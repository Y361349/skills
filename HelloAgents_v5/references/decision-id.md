# 决策ID（Decision ID）约定（HelloAgents_v5）

> 目的：把“关键取舍”写成可引用的编号，让后续排查/复盘/回归能快速回答：为什么这么做、当时有哪些替代、影响是什么。

## 1. 什么时候需要写

满足任一条件，建议写至少 1 条决策ID：
- 存在 2 条以上可行实现路径，需要权衡取舍。
- 引入新依赖/新框架/新存储/新中间件，或改动会长期存在。
- 接口契约/字段语义/状态枚举发生变化，需要统一口径。
- 数据迁移、权限/认证、安全策略调整。
- 需要“可回滚/可降级”的设计说明（开关、兼容策略、灰度等）。

## 2. 编号规则（推荐）

**决策ID格式：**`{package_name}#D{NNN}`
- `package_name`：方案包目录名，例如 `202602110930_add-erp-menu`（来自 `helloagents/plan/`）。
- `NNN`：三位序号，从 `001` 递增（同一个方案包内递增即可）。

示例：
- `202602110930_add-erp-menu#D001`
- `202602110930_add-erp-menu#D002`

## 3. 写在哪里（推荐）

- **首选**：写在 `helloagents/plan/.../how.md` 的“关键技术决策（Decision IDs）”章节中（详见 `templates/plan-how-template.md`）。
- **架构类决策**：可同时在 `wiki/arch.md` 的“重大架构决策”表中补一行索引，`details` 链接指向该 `how.md` 的小节。

## 4. 最小记录模板（建议）

```md
### {package_name}#D001: {决策标题}
**上下文:** {背景与问题}
**决策:** {核心决策}
**理由:** {为什么这么选}
**替代方案:** {方案A/方案B} → 拒绝原因: {原因}
**影响:** {后果、风险、兼容性}
**回滚/降级:** {开关/回滚步骤/数据兼容策略}
```

## 5. 怎么被引用（建议）

- **CHANGELOG 条目**：`决策: {decision_id}(一句话摘要)`（见 `templates/changelog-template.md`）。
- **记忆体**：在 `wiki/memories/...` 的“关键决策”列出决策ID（见 `templates/wiki-memory-template.md`）。
