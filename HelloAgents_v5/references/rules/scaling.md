# 项目规模判定与分批策略（HelloAgents_v5）

本规则用于 **项目分析（analyze）阶段**：
- 判定项目是否为“中/大型项目”
- 决定是否启用分批读取、分批写入、分批同步知识库

> 说明：规模判定不等于复杂度判定。复杂度判定主要由需求本身决定；规模判定用于控制“读取/写入批次”和“上下文预算”。

---

## 1. 大型项目阈值（与 `scripts/project_stats.py` 保持一致）

满足任一条件即可视为大型项目：
- 源代码文件数 > 500
- 代码行数 > 50000
- 模块数 > 30

建议使用脚本获取精确统计：

```bash
python -X utf8 "{SCRIPT_DIR}/project_stats.py" --path "<项目根目录>"
```

---

## 2. 分批读取策略

原则：
1. 先索引后精读（先 `code-index` 定位，再用 Desktop Commander 局部读取）
2. 每批只读“与当前任务强相关”的文件/模块
3. 任何时候避免一次性把全仓库读入上下文

推荐批次：
- 每批模块 ≤ 20
- 每批文件命中 ≤ 30（超过则继续细分）

---

## 3. 分批写入与知识库同步

当模块数量很多时：
- `wiki/modules/` 文档按模块分批创建/更新
- 每批完成后做一次最小一致性自检（链接/路径/索引）
- 避免在一次执行中重写大量 wiki 文件（降低冲突与回滚成本）

---

## 4. 分片建议（可选）

> 目的：避免单文件过大导致“难检索/难回滚/难协作”。

### 4.1 CHANGELOG 按年分片

触发（满足其一即可考虑）：
- CHANGELOG 条目数 > 200
- 跨年维护且历史条目增长明显

策略（建议）：
- `helloagents/CHANGELOG.md`：保留 `Unreleased` + 当前年份条目
- `helloagents/CHANGELOG_{YYYY}.md`：存放历史年份条目
- 任何条目中的“方案包/记忆体/决策ID”引用保持不变（尽量使用相对路径，避免移动后失效）

### 4.2 `wiki/modules/` 主题拆分

- 单模块页建议 ≤200 行（见 `templates/wiki-module-template.md` 的防膨胀约定）。
- 超出时拆分为：`wiki/modules/<module>-<topic>.md`，并在 `wiki/modules/<module>.md` 保留索引入口与关键链接。
